# Nuance — contributor notes

Mobile app that filters the camera feed in real time to help colour-blind people (protan, deutan,
tritan, total or partial) tell colours and contrasts apart. Kotlin Multiplatform with Compose
Multiplatform; Android first, iOS prepared. This file is the contributor guide for humans and AI
assistants alike. Read first:

- `README.md` covers what it does (in French).
- `docs/SETUP.md` covers the tools, wireless ADB, the signing key and the first install (in French).

## Commands

```bash
npm install          # also points git at .githooks/
npm run phone        # build the dev variant, install it on the paired phone, launch it (< 30 s)
npm run phone:find   # only (re)connect to the phone over wireless ADB
npm run phone:logs   # install, launch, then follow the app's log
npm test             # every Kotlin test, on the JVM (the CI also runs core on the iOS simulator)
npm run lint         # ktlint (Spotless) + Android Lint, warnings are errors
npm run format       # ktlint and Prettier, in place
npm run check        # what the CI's Linux job runs, but gitleaks on the history
```

With several phones paired, `nuance.phone=<serial number>` in `local.properties` (ignored) picks the
test phone. `npm run phone -- --connect <ip:port>` helps when mDNS advertises a stale address.

`npm install` points git at `.githooks/`:

- `pre-commit` runs gitleaks on the staged changes (install: `scoop install gitleaks`,
  `brew install gitleaks`…);
- `commit-msg` rejects messages that don't follow the commit rules below;
- `post-commit` re-dates each commit at noon UTC (see Privacy);
- `pre-push` runs `check:private`, the date check and the commit check.

## Commits

Follow [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/) strictly:

```
type(scope)!: imperative description, lowercase, no trailing period

Body explaining *why* (the diff already shows what).
```

- **Types:** `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `build`, `ci`, `chore`, `style`, `revert`.
- **Scope** is optional; `scripts/check-commits.mjs` holds the authoritative list of types and scopes.
- Header of 72 characters or fewer. One logical change and one type per commit.
- Code, comments and commit messages are in English; the UI (FR and EN) and the user docs are in French.
- Work happens on `main`; every push runs the CI.

## Privacy of the public repository

The repository is public. Nothing personal goes into code, tests, fixtures, docs, commit messages or
commit metadata.

- **No personal data:** names, e-mail addresses, local paths, device serial numbers or addresses.
- **No camera image, ever.** Test images are **synthetic**, generated by code (test charts, colour
  swatches, generated plates, artificial scenes), or clearly attributed under a free licence.
  `check:private` refuses any tracked JPEG, HEIC, DNG or video file.
- **Identity:** commit with a GitHub `noreply` address. `check:private` rejects any other.
- **Times:** commit times show when someone works. The `post-commit` hook keeps only the day (noon UTC);
  `npm run fix:dates` re-dates unpushed commits made without the hook (rebases, other machines).
  Release tags are lightweight, as an annotated one would record the time.
- **Docs only when they belong in public:** no personal to-do lists, plans or notes. Local working notes
  stay in `.claude/` (ignored).
- **Secrets:** the release signing key and its passwords live on the PC and in GitHub secrets only
  (`*.jks`, `keystore.properties` are ignored). gitleaks scans the staged changes and, in CI, the history.
- `.private-patterns` (ignored, one regex per line) lists your own private strings: `check:private`
  scans tracked files and commit messages for them.

## Invariants (discuss before changing)

- **Images never leave the phone.** No cloud processing, no telemetry, no analytics, no backend. The
  only network call is the update check against GitHub Releases: off by default, offered at first
  launch, with a "Vérifier maintenant" button that always works. Saved photos and videos carry no
  location. Nothing is backed up (`data_extraction_rules.xml`, `backup_rules.xml`).
- **Every colour treatment is a 3D LUT.** Simulation, correction, contrast, hue isolation: each mode is
  a pure function `(Rgb) -> Rgb` in `:core`, baked into a LUT off the render thread when a setting
  changes. The platform shader only samples the camera texture, then the LUT. Algorithms never touch
  shaders. Local treatments (CLAHE, edges) would be an extra GPU pass, outside v0.
- **Fluid or nothing.** The filter runs on the GPU: 30 frames a second steady in 1080p on the test
  phone, at most one frame of latency over the raw preview, no copy of a frame to the CPU in the
  render loop.
- **Simulations run in linear RGB.** Linearise sRGB before any matrix, re-encode after.
- **Not a medical device.** The built-in test gives an orientation, not a diagnosis; texts say so,
  without alarming. No promise to "cure" or to "restore normal vision".
- **Never colour alone.** No state, selection or alert in the UI is told by colour only: always a
  shape, an icon or a text too. Contrast ≥ 4.5:1, TalkBack/VoiceOver, system font size, touch targets
  ≥ 48 dp, reduced motion honoured. No Material You dynamic colours. Dark theme by default.
- **Common code never depends on Android.** `:core` is pure Kotlin; `:shared` reaches the platform
  only through interfaces (`CameraRenderer`…). The CI's macOS job compiles the iOS targets.
- **FR and EN from the start**, French with "tu", short and simple.
- **The dev variant only** (`.dev`, "Nuance dev") has the performance overlay, the fake camera
  source and the "take the test as a protan/deutan/tritan" switch. Never in a release.

## Layout

- `core/`: pure Kotlin multiplatform. Colour spaces, ΔE2000, deficiency models, corrections, LUT
  baking, profiles, the built-in test, colour naming. Tests in `src/commonTest`, run on the JVM.
- `shared/`: Compose Multiplatform UI, state, settings, FR/EN strings (`src/commonMain/composeResources`),
  the `CameraRenderer` interface. Android KMP library plugin (AGP 9).
- `androidApp/`: Android entry point, CameraX, OpenGL ES 3 rendering, MediaStore, APK updates.
- `iosApp/`: Xcode project (from the official KMP template, Apache-2.0), iOS 17+. It calls
  `:shared:embedAndSignAppleFrameworkForXcode`.
- `scripts/`: repository checks, git hook helpers, phone shortcuts.

## Dependencies

Keep them few, and say why in the commit that adds one. Versions live in `gradle/libs.versions.toml`.
Lock files and the Gradle wrapper are written by their tools (`gradle wrapper --gradle-version …`),
never edited by hand. Dependabot proposes grouped updates every Monday (Gradle, npm, Actions).

## Releases

Semantic versioning. `0.1.0` comes out when the app is ready for a first real tester. After it: `0.x.0`
for a milestone of features, `0.x.y` for fixes that matter between them; the smallest touches get no
version of their own and are listed under `## Depuis la dernière version` at the top of `CHANGELOG.md`.
`CHANGELOG.md` (in French, for users) says what each version brings (`## x.y.z — YYYY-MM-DD`, then
`### Nouveautés` / `### Corrections`). A lightweight tag `vX.Y.Z` makes `.github/workflows/release.yml`
publish the signed APK, its SHA-256 and that version's notes; `versionCode` derives from the version.
